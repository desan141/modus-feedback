# Результаты проверки 12 ноября 2026 года

## Среда и исходное состояние

Windows, Python 3.12.14. Использованы версии из requirements.txt и
requirements-dev.txt. Проверка `pip check` не обнаружила конфликтов зависимостей.
JavaScript проходит `node --check`.

Готовый ZIP отдельно распакован в проверочную папку. Команда `python main.py`
успешно запустила извлечённый проект: HTML и локальные стили отдаются, анонимный
API закрыт, вход и выход работают, снимок БД даёт 20 обращений, 15% завершённых,
9,93 часа первого ответа и три исходные просрочки. Проверена целостность ZIP.

Исходный комплект найден в распакованной папке employee-feedback-mvp-web.
Прежний README совпадал с поведением: переключатель был интерфейсным, защищённых
API не было, закрытие не требовало объяснения. Исходная версия запущена на
отдельной базе: главная страница 200, аналитика с контрольными значениями,
запрос `/tickets` без входа — 200. В новой версии тот же запрос — 401.
Все 20 текстов и кодов seed отдельно сопоставлены с Датасет.docx.

## Автоматические проверки

Фактический итог: **51 passed, 1 warning**.

Предупреждение — Starlette о будущей замене тестового клиента httpx;
оно не является ошибкой приложения или пропущенным тестом. Использованный
совместимый httpx закреплён в requirements-dev.txt.

Проверены:

- Запрет всех защищённых типов API без сессии, включая создание, выход и уведомления.
- Верный/неверный вход, срок сессии, отключённый пользователь, выход и отзыв токена.
- Отдельные id и Argon2id-хеши с разными солями; cookie HttpOnly/SameSite.
- CSRF и запрет записи с чужого Origin.
- Запрет подмены author_id, author_role, user_id, role; игнорирование попытки
  расширить доступ заголовком роли, query-параметрами или поддельной cookie.
- Запрет сотруднику читать, комментировать или менять чужую карточку, даже
  в том же подразделении; запрет ему менять статусы и маршрутизацию.
- Граница подразделения руководителя для карточки, переписки, истории и изменений.
- Чтение/редактирование правил администратором, основной/резервный маршрут,
  сохранение исторических назначений после изменения правила.
- Обязательный итог для закрытия, реализации и отказа: null, пусто и пробелы
  отклоняются без частичного изменения карточки.
- Допустимые переходы, первое время ответа, повторное открытие и история
  старых/новых значений с пользователем и временем.
- Комментарии, выборки, имена файлов и SLA 48 часов для высокого приоритета.
- Контрольные исходные метрики и аналитика в пределах прав; особенность отказа.
- Уведомления и запрет доступа к чужим уведомлениям, включая изменение
  доступности карточки по подразделению.
- Восемь одновременных созданий без повторных кодов.
- Повторная инициализация без потери комментариев, итогов, правил и событий.
- Миграция отдельной старой схемы: копия до изменения, сохранение всех исходных
  значений и неполных исторических итогов, отсутствие вымышленных авторов,
  отсутствие повторного импорта и повторной миграции.
- Главная HTML-страница и локальный tailwind.css без CDN.

Все эти тесты используют временные базы. Для запуска: `python -m pytest -q`.

## Браузер

Через работающий Uvicorn на отдельной БД пройдены:

1. Ошибка входа с неправильным паролем и успешный вход сотрудником.
2. Создание обращения и показ назначенной роли; карточка с событием создания.
3. Отправка комментария и отображение переписки отдельно от событий.
4. Выход и вход вторым сотрудником: чужое обращение отсутствует.
5. Вход руководителем, запрос уточнения, сохранение статуса и события истории.
6. Попытка отказа без объяснения: форма требует заполнить причину.
7. Сохранение отказа с причиной, отображение старого/нового значения в истории.
8. Получение автором уведомлений об уточнении и результате, отметка прочтения.
9. Вход администратором, редактирование резервной роли и ручная недоступность основного.
10. Новое обращение сотрудника получает изменённую резервную роль.
11. Поиск и фильтр просрочек: A-003, A-009, A-013.
12. Аналитика с подписью формул и ограничением выборки правами пользователя.

В финальном браузерном журнале ошибок нет. Сохранён `preview-v2.png`.
На скриншоте **отдельная тестовая база после действий**, поэтому там 22 обращения.
Чистая исходная база с 20 обращениями и исходными метриками проверена отдельно.
Макет наблюдался при обычной ширине окна и в узком окне; отдельный полный аудит
всех мобильных устройств и браузеров не проводился.

браузеров, корпоративного входа и реальных интеграций. Утверждения о готовности
к таким условиям из этих результатов не следуют.
