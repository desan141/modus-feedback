# Модус · Голос команды

Работающий локальный MVP для хакатона Pavlodar Hub и ГК «Модус Трейд».
Сотрудник создаёт обращение и обсуждает его, руководитель подразделения фиксирует
статус и результат, администратор управляет маршрутизацией. Права проверяются
сервером при каждом запросе, включая прямые обращения к API.

## Установка и запуск в Windows

Нужен Python 3.10+; комплект проверен на Python 3.12.14 в Windows.
Распакуйте архив в отдельную папку и откройте в ней PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Откройте [http://127.0.0.1:8000/](http://127.0.0.1:8000/).
Для остановки нажмите Ctrl+C в терминале.
Если порт занят старым приложением, остановите его в его терминале либо задайте
`$env:PORT = "8001"` перед запуском. Работающий старый процесс сам не получает
новую авторизацию: его нужно перезапустить с обновлёнными файлами и зависимостями.

После установки Python-пакетов веб-интерфейс и API работают без интернета.
`tailwind.css` уже собран локально из Tailwind CSS 4.1.18; Node.js, npm и CDN
для запуска не нужны. Пользовательские стили находятся внутри `index.html`.
Лицензия Tailwind включена в `TAILWIND-LICENSE.txt`.

## Демонстрационные аккаунты

Общий начальный пароль: **`ModusDemo123!`**.

| Логин | Учётная запись | Роль | Подразделение |
| --- | --- | --- | --- |
| `employee` | Анна | Сотрудник | Закупки |
| `employee2` | Илья | Сотрудник | Закупки |
| `manager` | Мария | Руководитель | Закупки |
| `admin` | Администратор демо | Администратор | Управление |

Имена вымышлены. Два сотрудника специально находятся в одном подразделении:
так можно показать, что совпадение подразделения не открывает чужую карточку.
Кнопки на экране входа только подставляют реквизиты. Вход выполняется настоящим
запросом с паролем; роль приходит из БД, а не из переключателя или localStorage.

`DEMO_PASSWORD` задаёт другой начальный пароль только для отсутствующих аккаунтов
при первом запуске. Существующие пароли повторный запуск не сбрасывает.
Подсказка на экране содержит стандартный пароль; при собственной настройке
вводите пароль вручную. Этот комплект с публичными демо-паролями предназначен
для локальной демонстрации.

## Права доступа

| Действие | Сотрудник | Руководитель | Администратор |
| --- | --- | --- | --- |
| Читать обращения и переписку | Только свои | Своего подразделения | Все |
| Создавать | В своём подразделении | В своём подразделении | В выбранном подразделении |
| Добавлять комментарии | В свои | В доступные | В любые |
| Менять статус, ответственного, итог | Нет | В своём подразделении | В любых |
| Читать и менять правила маршрутизации | Нет | Нет | Да |
| Аналитика | Только свои | По подразделению | По всей базе |

В меню сотрудника — «Мои обращения». Руководитель видит «Обращения подразделения»
и отдельно «Мои обращения». Администратор видит все обращения и собственные.
Прямой запрос чужой карточки, комментариев или истории возвращает 404 без
раскрытия её содержимого. Запрещённое действие возвращает 403; отсутствие
действующей сессии — 401. Фильтры сужают доступную выборку, а не расширяют права.

Автор (`author_id`, `author_role`) определяется сессией на сервере. Эти поля,
роль и произвольный `user_id` не принимаются в форме создания и комментариях.
Попытка их передать отклоняется. Подразделение сотрудника/руководителя тоже
проверяется сервером; его нельзя заменить на чужое в запросе.

## Сессия

Пароли хешируются Argon2id через `pwdlib[argon2]` с отдельной солью для каждого
хеша. В HttpOnly cookie хранится случайный токен, а в БД — только SHA-256 токена.
Сессия действует восемь часов. Выход удаляет серверную запись и cookie;
повторный вход в том же браузере отзывает предыдущий токен.

Cookie имеет `SameSite=Strict`. Записывающие API дополнительно требуют
`X-CSRF-Token`, полученный при входе или через `/auth/me`. Запросы записи с
неразрешённого Origin отклоняются. CORS не использует `*` с сессиями.
После выхода интерфейс очищает ранее загруженные данные.

Для локального HTTP `Secure` выключен; при размещении за HTTPS его можно
включить через `SECURE_COOKIES=1`. Установка демо-аккаунтов и сессий основана на
[документации FastAPI о хешировании](https://fastapi.tiangolo.com/tutorial/security/oauth2-jwt/)
и [параметрах cookie Starlette](https://starlette.dev/responses/).

## Существующая база и миграция

В комплекте есть согласованный снимок доработанной `feedback.db` и резервные
копии исходной схемы в `backups/`. Для обновления своего проекта сначала
остановите старый сервер, сохраните свою БД и замените файлы кода и стилей.
Не заменяйте свою БД файлом из архива, если после начала работы в ней появились
дополнительные данные. При старте код сам применит миграцию к вашей БД.

`migrations.py` перед изменением старой схемы делает согласованную копию через
SQLite Backup API: `backups/<имя>-pre-auth-<UTC-время>.db`. Затем добавляет
nullable `author_id` в обращения и комментарии. `main.py` создаёт новые таблицы
пользователей, сессий, истории, внутренних уведомлений и служебных меток.
Исходные поля, записи, комментарии, решения и маршруты не удаляются.

У исторических записей `author_id=NULL`. Они не приписаны Анне, Илье или другому
случайному человеку. Условные роли и исходные подразделения сохранены.
Такие записи видит администратор и руководитель соответствующего подразделения;
сотрудник их не получает. В карточке есть явная пометка. Для истории добавлено
одно событие «Импорт исторической записи» со временем миграции, а не выдуманная
история предыдущих изменений. Комментарии остаются отдельной перепиской.

На исходных 20 записях администратор видит все 20, руководитель закупок — четыре
(A-001, A-002, A-004, A-020), сотрудники — ноль. После создания новые записи
имеют настоящего автора. Перенос исторических записей на реальных пользователей
и управление аккаунтами через интерфейс пока не реализованы.

Повторный запуск не дублирует seed, пользователей и события импорта, не обновляет
старые даты и не сбрасывает настройки. Для восстановления остановите сервер и
используйте сохранённую копию как `DB_PATH`; старая схема снова будет мигрирована.

## Отдельная чистая база для защиты

Не удаляйте рабочую базу. Выберите **новое, ещё не существующее имя**:

```powershell
$env:DB_PATH = Join-Path (Get-Location) "defense-01.db"
$env:PORT = "8000"
.\.venv\Scripts\python.exe main.py
```

Создадутся 20 исходных обращений, 18 правил, четыре аккаунта и события импорта.
`python seed.py` также инициализирует базу по тому же `DB_PATH`, но ничего не
обнуляет. Для повторной чистой репетиции используйте другое новое имя файла.
Чтобы вернуться к `feedback.db`: `Remove-Item Env:DB_PATH`.

Тексты и коды seed сопоставлены с приложенным `Датасет.docx`: все 20 совпадают.
Подразделения, даты, комментарии, результаты и резервные роли — демонстрационные
дополнения прежнего MVP. При миграции эти дополнения сохранены.

Контрольные показатели чистой базы **для администратора**:

| Показатель | Значение |
| --- | --- |
| Всего | 20 |
| Проблемы / предложения / положительные отзывы | 9 / 10 / 1 |
| Завершено | 3, или 15% |
| Средний первый ответ | 9,93 часа по 15 обращениям |
| Просрочены сразу после инициализации | A-003, A-009, A-013 |

Даты генерируются один раз. Через несколько дней другие открытые обращения
тоже могут стать просроченными. Миграция не подгоняет даты под эти показатели.

## Обработка и история

| Из статуса | Допустимые следующие статусы |
| --- | --- |
| Новое | На рассмотрении, В работе, Ожидает уточнения, Отклонено, Закрыто |
| На рассмотрении | В работе, Ожидает уточнения, Реализовано, Отклонено, Закрыто |
| В работе | На рассмотрении, Ожидает уточнения, Реализовано, Отклонено, Закрыто |
| Ожидает уточнения | На рассмотрении, В работе, Реализовано, Отклонено, Закрыто |
| Реализовано, Отклонено, Закрыто | В работе, то есть явное повторное открытие |

Сохранить тот же статус разрешено. Для перехода в `Реализовано`, `Отклонено`
или `Закрыто` нужен непустой итог: новый либо уже сохранённый. Пробелы не
считаются объяснением. Очистить итог у конечного статуса нельзя. При отказе
в интерфейсе написано «Причина отказа». Сервер проверяет это независимо от формы.
Старые конечные записи с отсутствующим итогом при миграции не переписываются;
новая проверка применяется при сохранении статуса или решения.

Сотрудник отвечает на запрос уточнения комментарием. Статус меняет руководитель.
Возврата в `Новое` нет; при повторном открытии сохраняются итог и дата первого
ответа. История фиксирует создание, смену статуса, ответственного и решения:
время UTC, пользователя, действие, старое и новое значение. Изменение карточки
и события записываются одной транзакцией. Одинаковые значения не создают шум
в журнале. Комментарии не подменяют историю событий.

## Маршрутизация и метрики

Администратор редактирует основной и резервный **тексты ролей** и вручную
переключает доступность основного. При создании сервер читает актуальное
правило категории; недоступен основной — назначает резервного. Изменение
правила не переназначает прежние карточки. Календаря отпусков и справочника
реальных исполнителей нет.

Определения сохранены и подписаны в разделе аналитики:

- «Завершено» = количество `Закрыто` + количество `Реализовано`.
- Доля завершённых = это количество / число доступных обращений × 100%.
- Первый ответ — первый выход из `Новое`. Обычный комментарий его не меняет.
- Среднее — разность `first_response_at - created_at` только по записям с ответом.
  Для пустой выборки ответов возвращается `null`, а не ноль.
- SLA — календарные часы: высокий приоритет 48, средний 120, низкий 240.
- Просрочено = срок в прошлом и статус не `Закрыто`/`Реализовано`.
  Поэтому `Отклонено` не входит в «Завершено» и может быть просроченным.

Все показатели считаются в пределах серверных прав пользователя. Отдельного
показателя «Рассмотрено» нет. Время в API — UTC с `Z`, интерфейс показывает
локальное время браузера. Топ категорий сортируется по убыванию количества,
при равенстве — по названию.

## Внутренние уведомления

После проверки основного объёма добавлены уведомления в SQLite:

- Создание/переназначение — руководителям подразделения и администраторам.
  Это уведомления обработчикам о назначенной роли, а не персональная доставка
  реальному владельцу роли: справочника сотрудников нет.
- Статус «Ожидает уточнения» — установленному автору нового обращения.
- Итог или изменение итога в конечном статусе — установленному автору.

Для исторических авторов без id уведомления не придумываются. Доступны только
собственные уведомления о доступных карточках. Можно отметить прочитанными.
Показаны последние 100; обновление происходит при открытии раздела, кнопкой
«Обновить» и после действий. Нет push, email, WebSocket и внешних сервисов.

## API и ручная проверка

| Путь | Назначение |
| --- | --- |
| `POST /auth/login` | JSON `username`, `password`; возвращает пользователя и CSRF |
| `GET /auth/me`, `POST /auth/logout` | Текущая сессия и выход |
| `GET /metadata` | Доступные справочники формы, SLA и переходы |
| `GET /tickets` | Доступные карточки; фильтры `department`, `category`, `status`, `is_overdue`; `scope=mine` |
| `POST /tickets` | Форма: `type`, `category`, `text`; необязательные `priority`, `department`, `file` |
| `GET/PATCH /tickets/{id}` | Карточка; PATCH принимает только `status`, `assignee_role`, `final_resolution` |
| `GET/POST /tickets/{id}/comments` | Переписка; POST JSON только `text` |
| `GET /tickets/{id}/events` | История событий |
| `GET /routing-rules`, `PATCH /routing-rules/{id}` | Только администратор |
| `GET /analytics` | Только доступные данные; `top_limit=1..100`, `scope=mine` |
| `GET /notifications`, `PATCH /notifications/{id}/read` | Собственные уведомления; `unread_only=true` |

Пример для консоли разработчика на странице приложения:

```javascript
const session = await fetch('/auth/login', {
  method: 'POST', headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({username: 'employee', password: 'ModusDemo123!'})
}).then(r => r.json());
const form = new FormData();
form.set('type', 'Предложение');
form.set('category', 'Обучение');
form.set('text', 'Предлагаю практический семинар.');
const result = await fetch('/tickets', {
  method: 'POST', headers: {'X-CSRF-Token': session.csrf_token}, body: form
}).then(r => r.json());
console.log(result);
```

Авторские поля не отправляются. `Content-Type` для FormData браузер задаёт сам.
Сохраняется **только имя файла**, без пути; содержимое вложений не хранится.
Swagger доступен по `/docs`, OpenAPI JSON — `/openapi.json`. Страница Swagger
использует стандартные внешние ресурсы FastAPI; основной сайт от них не зависит.

Браузер отправляет запрос FastAPI. Зависимость проверяет cookie и загружает
пользователя; затем общий фильтр доступа ограничивает строки SQL. Обработчик
проверяет бизнес-правила и записывает изменения с историей в одной транзакции.
SQLAlchemy работает с одним SQLite-файлом. Всё запускается одним Python-процессом.

При получении исходников с GitHub базы и резервных копий в репозитории нет:
это ожидаемо. На первом запуске приложение само создаст новую базу с исходным
синтетическим датасетом. Готовый архив передачи проекта дополнительно содержит
снимок `feedback.db` и резервные копии; их не нужно загружать в репозиторий.

Настройки: `DB_PATH`, `PORT`, `DEMO_PASSWORD`, `SECURE_COOKIES`, `CORS_ORIGINS`.
Путь по умолчанию — `feedback.db` рядом с кодом, независимо от текущей папки.
Для нестандартного отдельного фронтенда явно задайте доверенные origins через
запятую. Встроенный интерфейс работает на том же origin и использует cookie.

## Границы MVP и следующие шаги

Реализован локальный процесс с серверными правами; это не промышленный IAM.
Нет регистрации, сброса пароля, редактирования пользователей, MFA, ограничения
частоты входа, HTTPS-сервера, реального справочника исполнителей и защиты журнала
от прямого редактирования владельцем SQLite-файла. Бэкапы перед миграцией есть,
регулярное резервирование и восстановление по расписанию пока не настроены.
Вложения — заглушки; SLA не учитывает рабочий календарь. Тесты не являются
нагрузочным аудитом или независимым аудитом безопасности.

После хакатона: администрирование аккаунтов, корпоративный вход, персональные
назначения, загрузка материалов с лимитами, производственные меры защиты,
рабочий календарь и уведомления в реальном времени. AI, 1С/Битрикс24,
микросервисы и замена SQLite в этот комплект не добавлялись.
